## 2. Admin TUI の起動と終了

### 2.1 起動方法

ホストOSにSSH接続後、Admin TUIバイナリを実行する。

```bash
# 環境変数を設定して起動
export VALKEY_PASSWORD=<Valkeyパスワード>
./admin-tui
```

| 環境変数 | 必須 | デフォルト | 説明 |
|----------|------|-----------|------|
| `VALKEY_PASSWORD` | Yes | - | Valkey認証パスワード |

> **注記:** Valkey の接続先は `127.0.0.1:6379` 固定である（環境変数では変更できない）。

### 2.2 起動エラー時の対処

Valkey接続に失敗した場合、以下のエラーダイアログが表示される。

       │                                                      │

       │                                                      │
       │          < Retry >     < Exit >                      │
       │                                                      │

| ボタン | 動作 |
|--------|------|
| `Retry` | Valkey接続を再試行 |

**確認事項:**
- Valkeyコンテナが起動しているか: `cd ~/eapaka-radius-server-poc/deployments && docker compose ps valkey`

## 3. 加入者管理（Subscriber Management）

メインメニューから `1` キーで遷移する。EAP-AKA認証に必要な加入者情報（IMSI, Ki, OPc, AMF, SQN）を管理する。

> **重要: 加入者の登録先は PLMN によって分かれる。**
> `VECTOR_GATEWAY_PLMN_MAP` で接続方式 `01`（aka-only-server）に向けた PLMN の加入者は、Ki / OPc を **aka-only-server**（Web GUI またはコマンド `subscriber add`）に登録する。この画面（Admin TUI の加入者管理）は、その PLMN の加入者には使わない。認可ポリシー（§5）と RADIUS クライアント（§4）は従来どおり Admin TUI で登録する（両方必要）。詳細は §3.5 を参照。

### 3.1 加入者一覧画面

```
┌ Subscriber List 1-9 of 9 (Page 1/1) ───────────────────────────────────────────────┐
│  IMSI             Ki              OPc              AMF    SQN            Created   │
│  001010000000000  465B5CE8...A6BC CD63CB71...2BAF  B9B9   000000000001   2024-01-01│
│  001010000000001  465B5CE8...A6BC CD63CB71...2BAF  B9B9   000000000021   2024-01-01│
│  001010000000003  465B5CE8...A6BC CD63CB71...2BAF  8000   0000000000c1   2024-01-01│
│! 001010000000007  465B5CE8...A6BC CD63CB71...2BAF  B9B9   ff9bb4d0b687   2024-01-01│
│! 441991234567890  465B5CE8...A6BC CD63CB71...2BAF  B9B9   FF9BB4D0B607   2024-01-01│
│  :                :               :                :      :              :         │
└────────────────────────────────────────────────────────────────────────────────────┘
F1:Help  |  q:Back/Quit  |  Ctrl+Q:Exit
```

#### 表示カラム

| カラム | 内容 | 備考 |
|--------|------|------|
| IMSI | 加入者識別番号（15桁） | ポリシー未設定時はYellow表示、行頭に `!` 表示 |
| Ki | 認証鍵（マスク表示） | 先頭8文字...末尾4文字（例: `465B5CE8...A6BC`） |
| OPc | オペレータ鍵（マスク表示） | 先頭8文字...末尾4文字（例: `CD63CB71...2BAF`） |
| AMF | 認証管理フィールド | 4桁Hex |
| SQN | シーケンス番号 | 12桁Hex |
| Created | 作成日 | YYYY-MM-DD形式 |

**ポリシー未設定の視覚的識別:** ポリシー（`policy:{IMSI}`）が登録されていない加入者は、行全体がYellow/Orange表示となり、IMSIカラムの先頭に `!` プレフィックスが付く。ポリシー未設定の加入者は認証時にAccess-Rejectとなるため、加入者登録後にポリシーの登録が必要である。

#### キーバインド

| キー | 動作 |
|------|------|
| `↑` / `↓` | カーソル上下移動 |
| `PgUp` / `PgDn` | 前のページ / 次のページ |
| `Enter` / `F3` / `e` | 選択した加入者の編集画面へ |
| `F2` / `n` | 新規登録画面へ |
| `F4` / `d` | 削除確認ダイアログ表示 |
| `F5` / `r` | 一覧を再読み込み |
| `F6` / `/` | フィルタ入力ダイアログ表示 |
| `Esc` | フィルタ適用中はフィルタを解除、それ以外はメインメニューへ戻る |
| `q` | メインメニューへ戻る |

#### ページネーション

1ページあたり50件を表示する。ボーダータイトルにページ情報（例: `1-50 of 125 (Page 1/3)`）が表示される。ページの切り替えは `PgUp`（前のページ）/ `PgDn`（次のページ）で行う。

#### フィルタ

`/` または `F6` キーでフィルタ入力ダイアログ（`Filter Subscribers`、入力欄 `IMSI contains:`）が表示される。入力した文字列を含む IMSI の行のみ表示する（部分一致、大文字小文字の区別なし）。`OK` で適用し、`Cancel` または `Esc` でフィルタを変えずにダイアログを閉じる。フィルタ適用時はボーダータイトルに `(Filter: "入力値")` が付加される。適用中のフィルタは、一覧画面で `Esc` を押すとクリアできる。

### 3.2 加入者の新規登録

一覧画面で `F2` または `n` キーを押すと、新規登録フォームが表示される。

```
              ┌ Create Subscriber ────────────────────────────────┐
              │                                                   │
              │  IMSI    [001010000000008       ]                 │
              │  Ki      [0123456789ABCDEF0123456789ABCDEF     ]  │
              │  OPc     [FEDCBA9876543210FEDCBA9876543210     ]  │
              │  AMF     [8000      ]                             │
              │  SQN     [000000000000   ]                        │
              │                                                   │
              │          < Save >  < Cancel >                     │
              │                                                   │
              └───────────────────────────────────────────────────┘
```

#### 入力フィールド

| フィールド | 必須 | 初期値 | 入力規則 |
|-----------|------|-------|---------|
| IMSI | Yes | 空 | 15桁の数字 |
| Ki | Yes | 空 | 32桁のHex文字 |
| OPc | Yes | 空 | 32桁のHex文字 |
| AMF | Yes | `8000` | 4桁のHex文字 |
| SQN | Yes | `000000000000` | 12桁のHex文字（初期値のままでよい。空欄にすると保存できない） |

**入力時の注意:**
- 入力中は文字種を制限しない（Hex以外の文字も入力できる）。入力内容は `Save` を押したときにまとめて検証される
- Hexフィールド（Ki, OPc, AMF, SQN）は小文字で入力してもよい。入力中の表示はそのままで、保存時に大文字に変換して保存される
- 各フィールドの前後の空白は保存時に取り除かれる

**保存時の動作:**
- 全フィールドを検証し、エラーがあれば保存せず、ステータスバーに最初の1件を表示する（例: `Validation error: IMSI: must be 15 digits`、空欄の場合は `Validation error: Ki: required`）
- 同一IMSIの加入者が既に存在する場合は登録できない（`Failed to create: subscriber already exists`）。既存の加入者を変更する場合は編集（§3.3）を使う

### 3.3 加入者の編集

一覧画面で加入者を選択し `Enter`、`F3`、または `e` キーを押すと、編集フォームが表示される。

```
              ┌ Edit Subscriber ──────────────────────────────────┐
              │                                                   │
              │  IMSI    [001010000000008       ]  (disabled)     │
              │  Ki      [0123456789ABCDEF0123456789ABCDEF     ]  │
              │  OPc     [FEDCBA9876543210FEDCBA9876543210     ]  │
              │  AMF     [8000      ]                             │
              │  SQN     [000000000000   ]                        │
              │                                                   │
              │          < Save >  < Cancel >                     │
              │                                                   │
              └───────────────────────────────────────────────────┘
```

- **IMSI** は読取専用（グレーアウト、編集不可）
- その他のフィールド（Ki, OPc, AMF, SQN）は編集可能。保存時の検証は新規登録（§3.2）と同じ
- 認証を行った加入者の SQN は小文字で表示されることがある（Vector API が認証のたびに小文字で書き戻すため）。そのままでよい

**保存時の動作:**
- SQN を変えずに保存した場合（Ki / OPc / AMF だけを変更した場合）は、SQN は書き換えられない。編集画面を開いている間に端末の認証が行われて SQN が進んでいても、その進んだ値が保たれる（フォームに表示されていた値に戻ることはない）。大文字小文字の違いだけでは SQN を変えたことにならない
- SQN を変えて保存した場合は、下記の警告ダイアログで `Continue` を選ぶと保存される
- 保存に失敗した場合は、ステータスバーにエラーが表示され、編集フォームのままとなる（主なエラーは下表）

| エラー表示 | 原因 | 対処 |
|-----------|------|------|
| `Failed to update: SQN was changed by authentication while editing. Reopen the subscriber and try again` | SQN を変えて保存しようとしたが、編集画面を開いている間に端末の認証が行われて SQN が進んでいた。何も保存されていない（Ki / OPc / AMF も変更されない） | `Esc` / `Cancel` で一覧に戻り、加入者を開き直して（最新の SQN が表示される）、改めて入力して保存する |
| `Failed to update: subscriber not found` | 編集画面を開いている間に加入者が削除された | 一覧に戻って状況を確認する |

#### SQN変更時の警告

### 3.5 aka-only-server に向けた PLMN の加入者（接続方式01）

Vector Gateway は IMSI 先頭の PLMN（MCC+MNC、5〜6桁）で認証ベクターの取得先を振り分ける。`VECTOR_GATEWAY_PLMN_MAP` で `01` を指定した PLMN の認証ベクターは aka-only-server が生成するため、その PLMN の加入者の Ki / OPc は aka-only-server に登録する。マップにない PLMN は従来どおり内部 Vector API（`00`）で、Admin TUI に登録した加入者が使われる。

#### 登録先の対応

| 登録データ | `00`（内部 Vector API、既定） | `01`（aka-only-server） |
|-----------|------------------------------|-------------------------|
| 加入者（Ki, OPc, AMF, SQN） | Admin TUI 加入者管理（§3） | **aka-only-server**（Web GUI またはコマンド `subscriber add`）。許可クライアントに `radius-gw`（vector-gateway のクライアントID）を含める |
| 認可ポリシー | Admin TUI（§5） | Admin TUI（§5） |
| RADIUSクライアント | Admin TUI（§4） | Admin TUI（§4） |

- auth-server はポリシー未登録の加入者を Access-Reject とするため、`01` の加入者も **aka-only-server への加入者登録と Admin TUI へのポリシー登録の両方が必要**である。
- Admin TUI の加入者画面（新規登録・編集・削除・CSVインポート）は `01` に向けた PLMN の加入者には使わない。登録しても認証には使われない。
- aka-only-server に登録した加入者は Admin TUI の加入者一覧に表示されないため、ポリシー未設定の `!` 表示（§3.1）では検出できない。ポリシーの登録はポリシー一覧（§5）で確認する。

#### 自分の PLMN がどちらに向いているかの確認

```bash
cd ~/eapaka-radius-server-poc/deployments

# PLMN マップと aka-only-server の接続先（例: VECTOR_GATEWAY_PLMN_MAP=44010:01）
grep -E "VECTOR_GATEWAY_(MODE|PLMN_MAP|AKAONLY_URL)" .env

# vector-gateway の起動ログ
docker compose logs vector-gateway | grep -E "starting vector-gateway|PLMN map refers"
```

| 確認項目 | 判定 |
|---------|------|
| `.env` の `VECTOR_GATEWAY_PLMN_MAP` | `PLMN:01` の形で書かれた PLMN が aka-only-server 向け。書かれていない PLMN は `00` |
| `.env` の `VECTOR_GATEWAY_MODE` | `passthrough` の場合はマップに関係なく全 PLMN が `00` |
| 起動ログ `starting vector-gateway` | `akaonly_enabled=true` で `01` が使える状態。`akaonly_transport` は `mtls` / `plain`（平文HTTP） / `disabled` |
| 起動時の WARN `PLMN map refers to a backend that is not configured; requests will fail with 501` | `01` を指定しているが `VECTOR_GATEWAY_AKAONLY_URL` が未設定。その PLMN の認証は失敗する |

個々の認証でどちらに振り分けられたかは、vector-gateway のログ `GW_ROUTE`（`backend selected`）の `backend_id` で確認できる。

#### aka-only-server への加入者登録

aka-only-server 側のホストで実行する（Web GUI からも登録できる）。

```bash
docker compose exec -T aka-only-server /aka-only-server subscriber add \
  -imsi <IMSI> -ki <Ki> -opc <OPc> -clients <radius-gw のクライアントID>
```

`radius-gw` のクライアントIDは、接続設定時の `client add` で表示されたID（例: `client 1 added (name=radius-gw ...)` の `1`）である（B-02 参照）。

| オプション | 既定値 | 説明 |
|-----------|-------|------|
| `-sqn` | `000000000000` | SQN 初期値 |
| `-amf` | `8000` | AMF |
| `-sqn-type` | `inc32` | SQN 増加タイプ（`inc1` / `inc32` / `inc33`）。既定の `inc32` を推奨 |
| `-allow-plain` | なし | 平文HTTP での払い出しを許可する |
| `-clients` | なし | 許可クライアントID（カンマ区切り）。`radius-gw` のIDを必ず含める |

登録後、Admin TUI で同じ IMSI の認可ポリシーを登録する（§5、O-02）。

#### 注意事項

- **SQN:** 内部 Vector API は SQN を +32 ずつ進める。aka-only-server では SQN 増加タイプ `inc32`（既定）が同じ挙動になるため `inc32` を推奨する。内部 Vector API で使っていた SIM を `01` に移した場合、初回の認証で再同期が1回走って追従する（認証は成功する）。
- **振り分けは PLMN 単位:** 同じ PLMN の IMSI を `00` と `01` に分けることはできない。PLMN を `01` に切り替える場合は、その PLMN の全加入者を aka-only-server に登録してから `.env` を変更し、vector-gateway を作り直す（`docker compose up -d vector-gateway`。同一ホスト構成では O-03 §5.2 の注意のとおりオーバーレイを重ねる）。
- **平文HTTP:** `VECTOR_GATEWAY_AKAONLY_URL` が `http://` の場合（同一ホスト内に限る）、加入者ごとに平文HTTP の許可（`-allow-plain`）が必要である。許可がない加入者は aka-only-server が 403 を返し、Access-Reject となる。
- **加入者データの保守:** `01` の加入者の Ki / OPc / SQN の変更・削除は aka-only-server 側で行う。Admin TUI のエクスポート（§6.2）には含まれない。

### 4.5 登録する IP アドレスと共有シークレット（運用上の注意）

Auth Server / Acct Server は、受信した RADIUS パケットの**送信元IPアドレス**でクライアント登録（`client:{IP}`）を引き、その Secret（共有シークレット）でパケットを検証する（D-09 §5.2、D-10 §4.2）。

#### 登録する IP アドレス

サーバーから見た AP（NAS）の送信元IPを登録する。AP 自身に設定した IP アドレスとは限らない。

| AP とサーバーの位置関係 | 登録する IP Address |
|------------------------|--------------------|
| 同じ LAN にある（NAT を挟まない） | AP の IP アドレス |
| AP が NAT（家庭・オフィスのルーター等）の内側にあり、インターネット越しにサーバー（VPS 等）へ送る | ルーターのグローバルIP |
| 同じホスト上から試験する（radclient / eapaka_test から `127.0.0.1` 宛てに送る） | Docker ブリッジのゲートウェイIP（例: `172.18.0.1`。確認方法は T-03 §2.2） |

- 同じ NAT の内側にある複数の AP は、サーバーからは同じ送信元IPに見えるため、同じ IP として扱われる（1つのクライアント登録・同じ Secret を共有する）。認可ポリシーのルールの `nas_id` は RADIUS の NAS-Identifier 属性で判定するので、ルールは AP ごとに分けられる（§5、O-02）。
- グローバルIPが動的に変わる回線では、IP が変わると登録のない送信元IPとして扱われるため、登録をやり直す必要がある。固定IPの回線が望ましい。
- インターネット越しに受ける場合は、クラウド側のファイアウォール（Lightsail のネットワーク設定のファイアウォール、セキュリティグループ等）で 1812/udp・1813/udp の送信元を AP のグローバルIPに絞ることを推奨する。Docker が公開したポートにはホストの UFW の規則が効かないため、`ufw allow from` では絞れない（D-01 §4）。

#### 共有シークレット（Secret）

- RADIUS（UDP）は共有シークレットだけで守られる（パケットの認証と MPPE 鍵の暗号化）。RadSec（RADIUS over TLS）は本PoCのスコープ外である。Secret は十分に長いランダムな値にする（例: `openssl rand -base64 24` で生成した値。§4.2 の入力規則を満たす）。
- AP 側の RADIUS サーバー設定（認証 1812・課金 1813）にも同じ Secret を設定する。

#### フォールバック（`RADIUS_SECRET`）を空にしている場合

- `.env` の `RADIUS_SECRET`（フォールバックの共有シークレット）は空を推奨する（インターネットに公開するサーバーでは空にする。B-02、D-08）。空のときは、クライアント登録のない送信元IPからのパケットは破棄され、応答しない。サーバーのログには `RADIUS_NO_SECRET`（WARN。`src_ip` に送信元IP）が出る（O-05）。
- AP から認証できず、`RADIUS_NO_SECRET` が出ている場合は、`src_ip` の値を確認し、その IP をクライアント登録する（登録はすぐに反映され、コンテナの再起動は不要）。

```bash
cd ~/eapaka-radius-server-poc/deployments
docker compose logs auth-server acct-server | grep RADIUS_NO_SECRET
```

- `RADIUS_SECRET` に値を設定していると、登録のない送信元IPからのパケットもその値で受け付ける（起動時に WARN が出る。D-09 §3.8）。

## 5. 認可ポリシー管理（Authorization Policy Management）— 簡易説明

### 5.1 概要

メインメニューから `3` キーで認可ポリシー管理画面にアクセスする。認可ポリシーはIMSI単位のアクセス制御を定義するもので、認証成功後にどのSSID/NASからの接続を許可するかを制御する。

### 5.2 画面構成の概要

認可ポリシー管理は以下の3階層で構成される。

**第1階層: ポリシー一覧画面**

登録済みポリシーの一覧（IMSI, Default Action, Rules数, 状態）を表示する。

```
┌ Authorization Policy List 1-9 of 9 (Page 1/1) ───────────────────────────┐
│ IMSI              Default   Rules       Status                           │
│ 001010000000000   allow     No rules    active                           │
│ 001010000000001   allow     No rules    active                           │
│ 001010000000002   deny      No rules    suspended                        │
│ 001010000000003   deny      1 rule      active                           │
│ 001010000000004   deny      2 rules     active                           │
│  :                :         :           :                                │
└──────────────────────────────────────────────────────────────────────────┘
```

- Default列: `allow` = Yellow/Orange表示、`deny` = Green表示
- Rules列: `No rules` / `1 rule` / `N rules` 形式
- Status列（r8）: `active`（利用中）= Gray、`suspended`（停止中）= Red。停止中の加入者は認証が拒否される（§5.4）

**第2階層: ポリシー詳細フォーム**

IMSI、Default Action（deny/allow）、ルールリストを編集する。Status（状態）は表示だけで、ここでは変えられない（保存しても停止のまま。停止・再開は一覧で行う。§5.4）。

**第3階層: ルール編集ダイアログ**

個別ルールのNAS ID、Allowed SSIDs、VLAN ID、Session Timeoutを設定する。`OK` を押したときにルールが検証され、エラーがあればステータスバーに表示される（例: `Validation error: NasID: required`）。

| フィールド | 必須 | 入力規則 |
|-----------|------|---------|
| NAS ID | Yes | 1〜253文字の印字可能ASCII（空白は使えない）。AP が送る NAS-Identifier と完全一致（大文字小文字を区別）で比較される。`*` 単独で任意のNASに一致 |
| Allowed SSIDs | Yes | カンマ区切りで1件以上（例: `CORP-WIFI,GUEST`）。各SSIDは1〜32文字 |
| VLAN ID | No | 空欄 または 0〜4094 の数字 |
| Session Timeout | No | 0〜86400（秒。`0` は未設定）。数字として解釈できない入力は `0` として扱われる |

ルールは0件でもポリシーを保存できる（その場合は Default Action だけで判定される）。ポリシーの保存時には IMSI（15桁の数字）と全ルールが検証され、ルールのエラーは `Validation error: Rules[0].NasID: required` のように何番目（0始まり）のルールかを示して表示される。同一IMSIのポリシーが既に存在する場合は新規登録できない（`Failed to create: policy already exists`）。

### 5.3 詳細操作

認可ポリシーの詳細な設定方法（NAS-ID/SSID設定例、VLAN割り当て例、トラブルシューティング）については、**O-02 ポリシー設定ガイド** を参照すること。

ポリシー管理画面の操作キーは他の一覧画面と共通（セクション3.1のキーバインド参照。フィルタ（`/` / `F6`）は IMSI が対象）。一覧でポリシーを選択して `Enter`、`F3`、または `e` キーを押すと、ポリシー詳細フォーム（`Policy Details`）が開く。削除時は加入者と同じ確認ダイアログ（`Confirm Delete`、`Are you sure you want to delete this policy?`、`Yes` / `No`）が表示される。

ポリシー詳細フォームでは、次のキーとボタンを使う。

| キー / ボタン | 動作 |
|--------------|------|
| `F6`（フォーム部分で） | ルールリストへフォーカスを移す（一覧画面の `F6` はフィルタ） |
| `Esc` / `Tab`（ルールリストで） | フォーム部分へフォーカスを戻す |
| `Enter`（ルールリストで） | 選択したルールの編集ダイアログ（`Edit Rule`）を開く |
| `Add Rule` ボタン | ルール追加ダイアログ（`Add Rule`）を開く |
| `Save` ボタン | 保存（Default を `allow` にした場合は警告ダイアログを表示） |
| `Cancel` ボタン / `Esc`（フォーム部分で） | 保存せずに一覧へ戻る |

一覧で `F7` / `s` を押すと、選択した加入者の停止・再開の確認ダイアログが表示される（§5.4）。

ルール編集ダイアログのボタンは `OK` / `Delete`（編集時のみ）/ `Cancel` である（ルール編集ダイアログは `Esc` では閉じない。`Cancel` で閉じる）。ルールの変更はポリシー詳細フォームの `Save` を押すまで保存されない。Default を `allow` にして保存すると、`Default Allow Warning` ダイアログが表示され、`Continue` で保存、`Cancel` で中止する。

### 5.4 加入者の停止・再開（r8）

加入者を登録したまま、一時的に認証できなくする（停止）・戻す（再開）。認可ポリシーに停止の印（`status`）を付ける仕組みで、Ki / OPc を本PoCに置く加入者にも aka-only-server に置く加入者にも同じように効く。

1. 認可ポリシーの一覧で対象の IMSI を選び、`F7` または `s` を押す。
2. 利用中の加入者では `Confirm Suspend`、停止中の加入者では `Confirm Resume` のダイアログが表示される。`Yes` で停止（再開）、`No` で中止する。
3. ステータスバーに `Subscriber suspended: {IMSI}`（`Subscriber resumed: {IMSI}`）が表示され、一覧の Status 列が変わる。

- 効くのは**次の認証から**である。接続中のセッションは切れない（停止しても今の接続は Session-Timeout や再認証まで続く）。
- 停止中の加入者が認証すると、Access-Reject になり、auth-server のログに `AUTH_SUBSCRIBER_SUSPENDED`（WARN）が出る（O-05）。
- 認可ポリシーのない加入者は停止できない（もともと認証は拒否される）。認可ポリシーを削除すると停止の印も消え、作り直すと利用中に戻る。
- 停止・再開は監査ログ（`operation` が `suspend` / `resume`）に記録される。Provisioning API（`PUT /policies/{imsi}/status`。D-13）からも同じ操作ができる。
- 詳細は O-02 §3.8 を参照。

## 6. インポート/エクスポート（Import/Export）

メインメニューから `4` キーで遷移する。加入者データ、RADIUSクライアント、認可ポリシーをCSVファイルで一括入出力する。

Import/Export メニューで `1`（Import）または `2`（Export）を選ぶ。`q` / `Esc`（または `(q) Back`）でメインメニューへ戻る。インポート画面・エクスポート画面では `Cancel` ボタンまたは `Esc` で Import/Export メニューへ戻る。

### 6.1 インポート操作

#### 手順

1. Data Type ドロップダウンからインポート対象を選択する（`Subscribers` / `RADIUS Clients` / `Policies`）
2. File Path にCSVファイルのパスを入力する
3. `Validate` ボタンを押してバリデーションを実行する（Phase 1）
4. バリデーション成功後、`Import` ボタンを押してインポートを実行する（Phase 2）

```
┌ Import Data ───────────────────────────────────────────────────────┐
│                                                                    │
│  Data Type    [Subscribers      ▼]                                 │
│  File Path    [/home/admin/import.csv                          ]   │
│                                                                    │
│  < Validate >  < Import >  < Cancel >                              │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
┌ Import Result ─────────────────────────────────────────────────────┐
│                                                                    │
│  (結果表示エリア — スクロール可能)                                      │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

#### 2フェーズインポート

| フェーズ | 動作 | エラー時 |
|---------|------|---------|
| Phase 1: Validate | CSVの全行を読み込み、バリデーション実行（入力規則は画面の登録と同じ。§6.3） | エラー一覧（`line {行番号}: {フィールド}: {内容}`）を結果エリアに表示、インポートは実行されない |
| Phase 2: Import | 全行を再度検証したうえで、Valkeyトランザクションで一括投入 | 1行でもエラーがあれば1件も投入しない。トランザクション失敗時はロールバック |

**注意:**
- `Validate` を押さずに `Import` を押しても、投入前に同じ検証が行われる
- 既に存在するキー（同じIMSI・IP）のデータは確認なしで上書きされる。上書きを避けたい場合は、事前にエクスポートでバックアップを取得する
- 加入者の SQN も CSV の値で上書きされる（加入者の編集（§3.3）と異なり、現在の SQN との比較は行わない）。以前にエクスポートした CSV をインポートし直すと、認証で進んだ SQN がエクスポート時の値に戻る

│                                                                    │

│                                                                    │

│  Imported: 15 subscribers                                          │
│                                                                    │

```

```

| カラム | 必須 | 説明 |
|--------|------|------|
| `ip` | Yes | 有効なIPv4アドレス |
| `secret` | Yes | 共有シークレット。1〜128文字のASCII印字可能文字（空白は使えない） |
| `name` | Yes | クライアント名称。1〜64文字の英数字・ハイフン・アンダースコア |
| `vendor` | No | ベンダー名。0〜64文字の英数字・スペース・ハイフン（空欄可） |

#### 認可ポリシーCSV

```csv
imsi,default,rules_json,status
440101234567890,deny,"[{""nas_id"":""*"",""allowed_ssids"":[""CORP-WIFI"",""GUEST""],""vlan_id"":""10"",""session_timeout"":7200}]",active
440101234567891,allow,[],suspended
```

| カラム | 必須 | 説明 |
|--------|------|------|
| `imsi` | Yes | 15桁の数字 |
| `default` | Yes | デフォルトアクション（`allow` または `deny`） |
| `rules_json` | No | ポリシールールのJSON配列（空文字列または `[]` で空ルール） |
| `status` | No | 状態（`active` または `suspended`。r8）。列がない CSV、または値が空の行は状態を変えない（新しいポリシーは `active`、既存のポリシーは今の状態のまま）。エクスポートは常にこの列を出力する |

`rules_json` の各ルールオブジェクト:

| フィールド | 必須 | 説明 |
|-----------|------|------|
| `nas_id` | Yes | NAS識別子（1〜253文字の印字可能ASCII、空白不可）。`*` 単独で任意のNASに一致（`AP-*` のような部分一致は不可）。それ以外は NAS-Identifier と完全一致（大文字小文字を区別） |
| `allowed_ssids` | Yes | 許可SSIDの配列（1件以上。各SSIDは1〜32文字） |
| `vlan_id` | No | VLAN ID（JSON文字列で指定。0〜4094 の数字） |
| `session_timeout` | No | セッションタイムアウト（秒。数値で指定。0〜86400） |

ルールのエラーは `line {行番号}, rule[{ルール番号（0始まり）}]: NasID: required` の形式で表示される。

#### 表示カラム

#### ソート切替

`s` キーを押すたびに、ソート対象が Start Time（デフォルト）→ NAS IP → IMSI → Start Time の順に切り替わる。向きはソート対象ごとに決まっており、切り替えることはできない。

| ソート対象 | 向き | 見出しの表示 |
|-----------|------|-------------|
| Start Time（デフォルト） | 新しい順（降順） | `Start Time ▼` |
| NAS IP | 昇順 | `NAS IP ▲` |
| IMSI | 昇順 | `IMSI ▲` |

NAS IP・IMSI が同じ行どうしは開始時刻の新しい順に並ぶ（開始時刻も同じ場合はセッションUUID順）。NAS IP は文字列として比較する（例: `172.19.0.10` は `172.19.0.9` より前に並ぶ）。

| `Enter` | Session Search 画面へ（IMSI検索ダイアログを表示。§7.4） |
| `Esc` | フィルタ適用中はフィルタを解除、それ以外はモニタリングメニューへ戻る |

### 7.4 Session Search

Session List画面でセッション行を選択して `Enter` キーを押すと Session Search 画面に移り、IMSI検索ダイアログ（`Search Sessions by IMSI`）が表示される。入力したIMSIのセッションを一覧表示する（選択した行のIMSIは自動では入力されない）。

**検索手順:**

1. Session List 画面でいずれかのセッション行を選択し、`Enter` キーを押す
2. IMSI検索ダイアログの `Enter IMSI:` にIMSI（15桁の数字）を入力する
3. `OK` ボタンを押す（`Cancel` または `Esc` でダイアログを閉じると、まだ検索していない場合は Session List に戻る）

> **注記:** Session List 画面の `/` キーはフィルタ（§7.3）であり、IMSI検索ではない。Session List にセッションが1件もない場合は `Enter` で Session Search 画面に移れない。検索は監査ログ（`AUDIT_LOG`、`operation`=`search`）に記録される（O-05 §11）。

│ 4673e913...     172.19.0.1                 02-22 22:41   22h 22m 2s     0B/0B      │

#### セッションテーブルの表示カラム

| カラム | 内容 | 表示形式 |
|--------|------|---------|

### 8.4 ダイアログ共通操作

Admin TUIでは以下の種類の確認ダイアログが表示される。

| 種別 | トリガー | 選択肢 |
|------|---------|--------|
| 削除確認（`Confirm Delete`） | 加入者/クライアント/ポリシーの削除操作 | `[Yes]` `[No]` |
| Default allow 警告（`Default Allow Warning`） | ポリシーのDefaultを `allow` に設定して保存 | `[Continue]` `[Cancel]` |
| SQN変更警告（`SQN Modification Warning`） | 加入者の編集でSQN値を変更して保存（大文字小文字の違いだけでは表示されない） | `[Continue]` `[Cancel]` |
| 接続エラー（`Connection Error`） | 起動時のValkey接続失敗（§2.2） | `[Retry]` `[Exit]` |

フォームを `Esc` / `Cancel` で閉じたとき、およびメインメニューで終了するときに確認ダイアログは表示されない。

上記の確認ダイアログで `Esc` を押すと、2つ目のボタン（`No` / `Cancel`。接続エラーでは `Exit`）を選んだときと同じ動作になる。

既存キーで新規登録しようとした場合は、確認ダイアログは表示されず、ステータスバーにエラー（`Failed to create: ... already exists`）が表示される。

加入者の編集で SQN を変えて保存したときに、編集中に認証で SQN が進んでいた場合は、ステータスバーにエラー（`Failed to update: SQN was changed by authentication while editing. Reopen the subscriber and try again`）が表示され、何も保存されない。加入者を開き直してやり直す（§3.3）。
